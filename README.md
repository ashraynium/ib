# IB Realms

IB Realms is a Rojo-based Roblox game foundation for a serious educational RPG where IB revision becomes structured adventure gameplay. Players build an IB profile, choose any number of supported subjects, enter subject-themed preview realms, complete question battles, unlock moves, track mastery, and return to a clean cosmic academy hub called the **IB Nexus**.

This version now targets the full IB Realms product foundation rather than only a first-build slice. It includes the hub, onboarding UI, dashboard, subject previews, topic-map UI, session progress, an expandable question bank, data-driven quests, a generated full campaign route and boss quest scaffold for every subject topic, a question-battle loop, preview zones for every supported subject, expanded loadout/rank systems, PvP/cosmetic data scaffolds, and a deeper Computer Science Hardware demo chain.

## Running with Rojo

1. Install Rojo.
2. Open this folder in VS Code.
3. Run:

   ```bash
   rojo serve
   ```

4. Open Roblox Studio with a blank Baseplate.
5. Use the Rojo Studio plugin to connect to the local server.
6. Press Play.

Rojo maps:

- `src/shared/IBRealms` -> `ReplicatedStorage.IBRealms`
- `src/server` -> `ServerScriptService.IBRealms`
- `src/client` -> `StarterPlayer.StarterPlayerScripts.IBRealmsClient`

## What to test first

1. Confirm Rojo creates `ReplicatedStorage.IBRealms`, server scripts, and `IBRealmsClient`.
2. Press Play and confirm there are no major red startup errors.
3. Confirm the player spawns safely on the glowing pad in the IB Nexus.
4. Confirm the HUD appears immediately.
5. Watch the title overlay: **IB Realms** and the subtitle.
6. Confirm first-time subject selection opens.
7. Add any number of subjects and confirm the Dashboard updates.
8. Open Computer Science, enter the System Core preview, and start **Boot Sector**.
9. Answer correctly and incorrectly; confirm enemy HP, focus, feedback, common mistake text, XP, and weaknesses update.
10. Complete the quest and confirm Debug Pulse, rewards, rank/loadout previews, and Return Hub work.

## Adding a new question

Questions live in ModuleScripts under:

```text
src/shared/IBRealms/Data/QuestionPacks
```

Create a new ModuleScript returning an array of question tables, then register it in:

```text
src/shared/IBRealms/Data/QuestionBank.lua
```

A question should use this shape:

```lua
{
    id = "unique_question_id",
    subjectBase = "computer_science",
    subjectIds = { "cs_hl", "cs_sl" },
    topicId = "cs_hardware",
    subtopic = "cache",
    learningObjective = "Explain why cache can reduce CPU waiting time.",
    difficulty = 2,
    commandTerm = "explain",
    type = "multiple_choice", -- or "text"
    prompt = "Why can cache improve CPU performance?",
    options = { "...", "...", "...", "..." },
    answer = 2,
    acceptedAnswers = { "..." },
    acceptedKeywords = { "cache", "frequently", "cpu" },
    markscheme = { "Point 1", "Point 2" },
    explanation = "Short teaching explanation shown after the answer.",
    commonMistake = "Targeted misconception feedback.",
    tags = { "cache", "performance", "understanding" },
    xp = 15,
    damage = 30,
    masteryImpact = { cache = 3 },
    sourceNote = "Original teacher note or syllabus objective reference."
}
```

Do not copy paid IB Questionbank, textbook, or past-paper questions unless you own the rights and have permission. The intended workflow is to create original questions from syllabus objectives, teacher notes, uploaded summaries, or user-provided revision notes.

## Attaching questions to quests

Quests use a `questionFilter` rather than hard-coding question IDs for normal play. A filter can include:

```lua
questionFilter = {
    subjectBase = "computer_science",
    subjectId = "cs_hl",
    topicId = "cs_hardware",
    minDifficulty = 1,
    maxDifficulty = 3,
    commandTerm = "explain",
    tags = { "cpu", "memory" },
    questId = "cs_boot_sector"
}
```

Normal quests pull from pools. Bosses can later add curated fixed question IDs if needed.

## Adding a new quest

Add a quest table in:

```text
src/shared/IBRealms/Data/QuestData.lua
```

A quest should define: `id`, `subjectId`, `subjectBase`, `topicId`, `title`, `questType`, `giver`, `briefing`, `startDialogue`, `objective`, `enemyName`, `enemyHP`, `playerFocus`, `questionFilter`, `rewardXP`, `rewardCoins`, `moveUnlock`, `badgeUnlock`, `tokenUnlock`, `unlocksNextQuest`, and `completionDialogue`.

## Adding a new subject

Add one subject table to `SubjectData.Subjects`, add or reuse topic IDs in `SubjectData.Topics`, create quests in `QuestData`, add questions in a question pack, and add preview-zone art or teleport support in `WorldBuilder` if it needs a new physical space.

The UI reads from `SubjectData`, so subject cards, dashboard entries, previews, and topic maps do not need to be manually duplicated.

## DataStores

Studio testing uses session-only data by default. The flag is:

```lua
GameConfig.UseDataStores = false
```

Keep this off until the game is published and Roblox API services are enabled. The profile shape already includes selected subjects, main subject, XP, coins, rank, subject progress, completed/unlocked quests, mastery, mistakes, unlocked moves, badges, tokens, active quest, current subject, and stats.

## Full-campaign scaffold

Every subject topic now receives generated route and boss quest IDs in the form:

```text
<subjectId>_<topicId>_route
<subjectId>_<topicId>_boss
```

For example, `physics_hl_physics_waves_route` starts the Wave Chamber route and `business_sl_business_finance_boss` starts the Finance District boss scaffold. Topic Map buttons can launch these routes directly. Generated quests use `CurriculumData` for learning scope, memory anchors, enemy identity, route/boss intent, rewards, badges, and tokens.
